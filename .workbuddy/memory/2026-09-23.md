### 三个必须处理的陷阱（详见 HANDBOOK 十五）

1. **SystemExit 会静默杀死请求线程**：`run_check`/合规闸用 `sys.exit(2)`，而
   `SystemExit` 继承 `BaseException`、`socketserver` 只捕 `Exception` → 请求线程
   静默结束、客户端收空响应。**必须先知道这件事**，否则会以为「前端没反应」去查 JS
2. **只给退出码 = 用户看不到原因**：合规闸 `print(reason, stderr); sys.exit(2)`
   把原因与机器码**分开传** → 界面只显示「合规闸拒绝（exit 2）」。修后实测回出
   「目标 'evil.example.com' 不在授权范围（来源 --scope）内」
3. **界面自律钳制**：`interval≥6s` / `max_requests≤10` 强制钳并回显 `clamps`；
   靶场用 **monkeypatch `webui.MIN_INTERVAL`** 改小值，不在生产代码开环境变量后门

### ⚠️ 新发现的真实缺陷：Windows 文件名 ADS（已修）

host 带端口 → `rules_127_0_0_1:18445.json` 的 `:` 被 NTFS 当 **alternate data
stream**：文件本体 **0 字节**、内容藏在隐藏流里，而 `os.path.isfile()` 与
`getsize()` **全部正常**（实测 True / 1854 bytes），`ls` 却显示 0 字节 ——
复制 / 打包 / 提交时内容直接丢失。**CLI 的 cmd_check 同样中招**
（`target.replace('.','_')` 也留 `:`）。已抽 `safe_evidence_name()` 修两处，
靶场两条断言锁住。**教训：所有校验都通过、只有人眼能发现的失效，
必须从命名层堵掉。**
