### ⭐ 新增可复用手法（4 条）

1. **安全头"占位符污染"检测** —— 值不是标准值而是 `value`/`off`/模板变量，

4. **归属证明从前端 bundle 页脚取证** —— Vue/React SPA 无服务端页脚时，
   去 `app.<hash>.js` 里搜「版权所有 / ICP / 有限公司」。
   比查备案库更硬（站点自身声明），且一次拿全主体+地址+备案号

3. **负结果与发现同等重要**

### 踩坑（代码层面）

- `OpenerDirector.open()` **不接受 `context=` 参数**（只有 `urlopen` 接受）
  → 自签证书/不校验 TLS 必须把 ctx 装进 `HTTPSHandler(context=ctx)`。
  错误表现是所有请求 status=None，很容易误判成网络不通
- `build_opener` 装了自定义 handler 后，30x 会被 `_NoRedirect` 转成 HTTPError，
  要手动从 `e.headers` 取 Location（这正是「明文是否跳转」的判据来源）
- 正则 `Powered\s*by\s*<[^>]{0,80}>?` 中 `<...>` 必须整体可选 `(?:<[^>]*)?`，
  否则强制要求存在 '<'，纯文本页脚全部漏匹配
- 靶场用「协议嗅探」单端口同时服务 HTTP/HTTPS（首字节 0x16 = TLS ClientHello），
  这样规则对同一 host 分发 https/http 都能落到同一个 handler


### ⚠️⚠️ 重大证据更正（本轮最重要产出）

**此前所有『明文 HTTP 200 不跳转』的结论都是错的 —— 实测全部是 301 跳转。**

根因：`manual_probe.py` 用 `urllib` 默认行为**自动跟随重定向**，301 被跟随成落地页的 200，
脚本把它记成「明文可达、不跳转」。规则引擎用了 `_NoRedirect` 才暴露真相。

复核结果（2026-09-22）：
```

http://bbs.ikuai8.com/         → 301（含 admin.php 也是 301）
http://qmt.jiaoyu.cn/          → 301
http://www.jiaoyu.cn/          → 301
```

## 2026-09-22 架构盘点：识别出的优化缺口（按复利排序）

**P0 最后一公里断裂（最硬）**：`cmd_check` 只写 `rules_<host>.json` 到 ROOT，
**不写入 session**；而 `generate_report(session, index)` 只读 `session["findings"]`
（autorun/扫描器产物），而 autorun 被 `allow_scanner=false` 闸死。
→ 真实 SRC 场景下 **report 永远为空，报告只能手写**（今天两份 700 行报告都是手搓的）。
修法：check 结果写进 session；report 支持渲染规则引擎 findings（含 negative /
unfinished / supersedes / 关联条目）；新增 `submit` 子命令按补天 6 项模板出稿。

**P1 evidence lint（今天两次翻车的直接产物）**：对 findings 原始证据跑断言 ——
声明"明文可达"却贴 200 / 属性缺失却写成值 / 响应 hash 与首页相同却判泄露 /
报告写"不跳转"但证据里有 Location。把人的失误变成机器的断言。

**P2 框架指纹 → 定向检查清单**：8 条规则全是通用配置类。
需 `rules/data/stacks.json`：指纹（laravel_session / X-Powered-By: ThinkPHP /
Discuz 页脚）→ 该栈定向检查项（debug 开关、/.env、/vendor、后台路径、官方公告源）。

**P3 覆盖度量化**：现在的覆盖度章节是文字，应算出「跑了 N 条 / 排除几条 /
预算是否耗尽 / 匿名态 vs 登录态」。

**P4 登录态建模**：教育/政务类站点天花板就是匿名态，应支持用户提供 Cookie 后跑同一套规则。

**明确反对的方向**：自动利用（SRC 禁）、LLM 自动判漏洞（幻觉 + 违反 confidence 模型）、
并发加速（限速是合规特性不是性能问题）、接 nuclei 模板（别绕 allow_scanner 闸）。
