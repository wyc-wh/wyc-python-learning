### 2. 修复 nmap 输出编码乱码（真实 bug）
- 现象：NSE 输出 `\xE9\x9B\xB7\xE7\xA5\x9E002`（实为"雷神002"），报告显示乱码

- 修复：scanners.py 新增 `_sanitize_text()`：① `re.sub(r'(?:\\x[0-9A-Fa-f]{2})+', ...)` 解转义→字节→UTF-8；② 去控制字符；③ latin-1→UTF-8 兜底
- 应用点：`_parse_nmap_xml`（service/product/version/scripts）+ `_parse_nuclei_json`（name）
- 验证：`_sanitize_text(r'\xE9\x9B\xB7\xE7\xA5\x9E002')` → `雷神002`；真实 nmap rdp-ntlm-info 中文正确还原

### 3. 报告增强（体现 Npcap 价值）

## 真实任务就绪度排查：修复「nmap 被误判未安装」的两个真根因

### 背景
回答「可以进行真实任务测试了吗？」时复测 e2e，发现报告一直写
`引擎=内置 stdlib 引擎（nmap 未安装）`，但 `install_tools.py --check` 显示
nmap 7.92 可用。追查发现**两个独立 bug 叠加**，都不是"沙箱限制"（之前误判为沙箱问题）。

### 根因 1：GBK 输出被 utf-8 解码丢弃
- `subprocess.run(..., encoding="utf-8", errors="ignore")` 在中文 Windows 下把
  nmap 的 GBK 输出**整段丢弃** → stdout 空串 → 上层判"工具不可用"→ 静默降级
- 修复：新增 `_decode_out()`（utf-8→gbk→cp936→latin-1 多编码回退），`_run_cmd` 改为
  bytes 捕获 + 多编码解码；`_nmap_has_npcap` 读 stderr 也过 `_decode_out`

### 根因 2（更隐蔽）：端口参数 `.split()` 丢掉 `-p`
- 代码：`port_arg = ",".join(ports) if ports else "--top-ports 100"` 然后 `.split()`
- 固定端口列表时 `-p` 从未进入命令行 →
  `nmap -sV -sC --open -oX - 135,445,3389,8080 127.0.0.1`
  → nmap 把端口串当**目标主机名**解析 → 卡满超时
- **判别指纹：耗时恰好 241.0s = 120s×2 次分支**（"太整齐"的耗时就是线索）
- 对照实验：同机同命令**只差 `-p`** → 有 `-p` 21.0s 成功 / 无 `-p` 120.0s 超时
- 修复：分支化拼装 `["-p", "135,445"]` / `["--top-ports", "100"]`，不再通用 split
- 防御：`_run_cmd` 加超时告警（>90% 打 WARN，超时打 `[TIMEOUT] <完整命令>`），
  并在 except 里区分 `TimeoutExpired`

### 附带修复
- `scanners.run_scan` 新增 `nuclei_ran` / `nuclei_ready` 字段 →
  覆盖度报告可区分「跑了没命中」vs「压根没跑」（原措辞一律说"工具未安装"误导性强）
- `_sanitize_text` 的 `\xNN` 字面转义解码正则修正：
  原 `(?:\\x[0-9A-Fa-f]{2})+` 会把 `\x000`（=0x00 + 裸字符 '0'）整体吃掉；
  改为 `\\x[0-9A-Fa-f]{2}(?:\\x[0-9A-Fa-f]{2})*`（每个转义必须自带 `\x` 前缀）
  - 验证 4/4：`\xE9\x9B\xB7\xE7\xA5\x9E002`→`雷神002`；
    `\x96\xF7y^\x000\x000\x002`→`桏y^002`（`桏` 是机器自签证书本身的原始 GBK 字节，非我方 bug）

### 验证结果（修复后）
- `nmap_scan()` **50.2s 返回 3 条真实服务**：135 msrpc / 445 microsoft-ds / 3389 ms-wbt-server
- `run_recon()` 44.8s，`nmap_enriched=True`
- NSE 拿到 `rdp-ntlm-info`（主机名 `雷神002`、`Product_Version 10.0.19041`）+ ssl-cert/ssl-date
- e2e 全绿：报告 `引擎=nmap 深度探测`，**发现数从 3 条涨到 5 条**（MSRPC/RDP 进去了）
- 报告含置信度列 + 覆盖度与结论边界 + 结论适用边界
- 编译 5/5；CVSS 自检 11/11（3.1×4 + 4.0×3 + 置信度×4）

### 教训（可复用）
1. **"工具没装"往往是调用侧问题**，先看 `_which()` 有没有值、`repr(stdout[:200])` 是不是空
2. **耗时是强信号**：恰好是超时值的整数倍 = 参数拼错（进程在等解析），不是网络慢
3. 外部命令封装**必须回显完整命令 + 超时告警**，否则这类错误永远不可见（被吞成"无结果"）
4. 不要轻易把问题归因于"沙箱限制"——本次就是连续两次误判为沙箱，实际全是自身代码缺陷

### 关键发现与教训
1. **git 之前被误判「不可用」** —— 实际 PortableGit 里就有 2.55.0，在
   `PortableGit\versions\1.2.0\cmd\git.exe`（注意是 `cmd/` 不是 `bin/`），只是没进 PATH。
   **「已装但没进 PATH」≠ 缺失**，先 glob 找便携版目录，找到就只做 shim，别重新下载/别动 UAC 安装器
2. **gobuster/feroxbuster 曾被误判「无 Windows 包」** —— 我的 asset 过滤器只认 `amd64`，
   但 gobuster 用 `Windows_x86_64`、feroxbuster 用 `x86_64-windows`。
   规则改为 `(amd64 OR x86_64) AND windows`，排除 arm64/i386/debug
3. **Go 系工具版本号必须先剥 ANSI 色码** —— `[\x1b[34mINF\x1b[0m] Current Version: v2.16.0`
   用裸正则 `v?([\d.]+)` 会匹配到颜色码里的 `34`。锚点统一用 `Current Version:`。
   各工具锚点不同（ffuf=`ffuf version:`；wafw00f 藏在 ASCII banner 后的
   `[+] The version of WAFW00F you have is vX.Y.Z`；gobuster **没有** `version` 子命令要用 `--help`）
4. **`python -m wafw00f` 报错** —— wafw00f 2.x 无 `__main__.py`，
   必须转发到 pip 生成的 console script（`venv/Scripts/wafw00f.exe`）
5. **非 exe 工具要在 `_find_exe` 里支持 `.bat`/`.cmd`/`.py`**，否则 sqlmap/wafw00f 被误报缺失。
   bat 里 `%~dp0` 以反斜杠结尾，直接拼引号会失效，要写 `"%~dp0.\sqlmap.py"`（插个 `.` 吃掉尾斜杠）
6. **批量下载会被沙箱 SIGTERM** —— 一次装 5 个 Go 工具（~60MB）被网关掐断；
   改为 `--only xxx` 逐个装即稳定。GitHub 直连 releases 常返回 10053/Tunnel 502，ghfast 镜像可用
7. **interactsh-client 默认连 oast.online 会被网关拦**（同 nuclei 的 `-no-interactsh` 坑），
   必须自建 interactsh-server 再 `-server` 指向

### 技术发现（实测）
- **F-01 中危**：`http://www.ikuai8.com/` 明文 200 不跳转 HTTPS + Cookie 仅 HttpOnly 无 Secure/SameSite + 无 HSTS
  → CVSS3.1 **5.3** / CVSS4.0 **4.8**（用本平台 cvss.py 双标准算）
- **F-02 低危**：HSTS / X-Frame-Options / CSP / Referrer-Policy / X-Content-Type-Options 全缺失
- **F-03 信息**：robots.txt 是 Joomla 默认模板残留（15 条 Disallow），但路径不存在
- **F-04 信息（企业自查，不提交 SRC）**：crt.sh 226 条记录 / 40 主机名，
  暴露 `jenkins.corp` / `harbor-dev.internal` / `kiam.corp-dev` / `wiki.corp` / `posthog.corp` 等内部系统
- 正向结论：TLS1.0/1.1 已拒绝，协商 TLS1.3 + TLS_AES_128_GCM_SHA256

### 关键方法论（可复用）
1. **软 404 必须用 sha256 比对判定**，不能只看状态码：
   `/administrator/` 返回 200 但与首页 `sha256` 完全相同（`ea964e54...`）→ catch-all 回退，非真实后台
   而 `/installation/` 是真 404。**只看 200 会误报「后台入口泄露」**
2. **sitemap.xml 是判断攻击面的最快手段**：421 条 URL 中动态入口（`.php`/`.asp`/`?`）**0 条**
   → 直接得出「全静态展示站，弱口令/SQLi/上传类攻击面基本不存在」的结论，
   比盲目扫一遍更符合公益 SRC 合规
3. **被动情报优先级**：crt.sh（226 条，需 `dangerouslyDisableSandbox` 出网）>> subfinder（无 API Key 返回 0）
   AliDNS DoH 解析 + crt.sh 即可完成资产盘点，全程不触碰目标
4. **发现的敏感内部域必须立刻写进 out_of_scope 并在审计链留 SCOPE-GUARD 条目**，
   报告里单列「企业自查项」，**绝不作为 SRC 漏洞提交**（提交=未授权测试取证）
5. **弱口令类需求**：先确认目标是否有登录入口，无入口就直说「攻击面不存在」，
   并给出报备后的合规方案（单账号×≤5 次、间隔 ≥10s、禁字典爆破、成功即停）
