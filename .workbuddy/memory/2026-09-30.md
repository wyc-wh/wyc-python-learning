### 工程突破：境外扫描中国目标被地域封锁 → 反向 SSH 隧道走国内出口
- 现象：同一域名境外（154.12.17.241）403、本地（中国）200 —— 萤石系站点对境外 IP 直接拦。
- 方案：`ssh -R 1080 -N root@server`（反向**动态**转发）→ 宿主 `127.0.0.1:1080` 成为 socks5，出口=本机；nuclei `-proxy socks5://127.0.0.1:1080`。
- ⚠️ 三个坑：① **容器内连不到宿主 127.0.0.1:1080**（网络命名空间隔离）→ nuclei 必须装在**宿主**（`/opt/nuclei-bin/nuclei`，github 可下载）；② `nohup ... &` 会让 paramiko `stdout.read()` 等不到 EOF → 必须 `setsid ... </dev/null >log 2>&1`；③ paramiko exec 的复杂嵌套引号一律改**上传脚本再执行**。

## ⭐ 提交稿「串稿」缺陷（本轮最实质的修复）
**现象**：`submit --rule R003` 出 2 条，条目 1（`act.biomart.cn`）里印的是条目 2（`xiaoyuan.jobmd.cn`）的复核取证。
**根因**：`orchestrator._verify_rule` 把人工复核记录**按 `rule_id` 单条**存放（`ver[rid] = {...}`），多位置复核时**后写覆盖先写**；`_submission_block` / `report` / SARIF / `evidence_lint` 也全按 `rule_id` 取 `evidence`。两个后果：
- ① 多位置复核互相串稿（取证张冠李戴，厂商一核即驳，伤的是提交者信誉）；
- ② **升级一处 → 同规则未复核的其他位置一起被标 confirmed 进提交稿/SARIF/报告**（比①更危险：把没验过的当验过的交出去）。
**修法**：
- `cvss.py` 新增 `norm_verify_key(host, location)`（键 = `站点|归一化路径`）与 `find_verification(verifications, rule_id, host, location)`、`has_legacy_verification()`。
- ⚠️ **键里必须带站点**：`_norm_location` 把 URL 剥成纯路径，`https://act.biomart.cn/` 与 `https://xiaoyuan.jobmd.cn/` 都归一成 `/`。且 `location` 本身是 URL 时**以其 host 为准**（导入数据形态下 location 主机可能与 `rule_checks` 键不同，只取一个都会折叠错）。
- 存储改为**每处发现一份记录**（`records`），顶层**刻意不写 `level`** → 任何遗漏改造的旧消费方 `.get("level","detected")` 会**回落到「疑似」**，失败方向安全（宁可不提交，也不能把没复核的当已复核）。
- 未登记的位置 `find_verification` 直接返回 `None`，**不退回规则级**（那正是串稿来源）；旧格式（规则级单条）仅作历史兼容，且 `submit` 出稿时**明写告警**「旧格式、位置不精确」。

## ⚠️ 两个必须记住的工具坑（都是「本地全绿、真跑才崩」）
