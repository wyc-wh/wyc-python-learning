## 00:20-01:10 「能挖到中高危吗」攻坚一轮（YSRC 萤石）— 结论：未出新的中高危

### 工程突破：境外扫描中国目标被地域封锁 → 反向 SSH 隧道走国内出口
- 现象：同一域名境外（154.12.17.241）403、本地（中国）200 —— 萤石系站点对境外 IP 直接拦。
- 方案：`ssh -R 1080 -N root@server`（反向**动态**转发）→ 宿主 `127.0.0.1:1080` 成为 socks5，出口=本机；nuclei `-proxy socks5://127.0.0.1:1080`。
- ⚠️ 三个坑：① **容器内连不到宿主 127.0.0.1:1080**（网络命名空间隔离）→ nuclei 必须装在**宿主**（`/opt/nuclei-bin/nuclei`，github 可下载）；② `nohup ... &` 会让 paramiko `stdout.read()` 等不到 EOF → 必须 `setsid ... </dev/null >log 2>&1`；③ paramiko exec 的复杂嵌套引号一律改**上传脚本再执行**。
- ⚠️ **最大教训**：用自己出口 IP 跑了约 4 万请求后，**本地 IP 被萤石 WAF 拉黑**（www.ezviz.com/www.ys7.com 从本机访问变 403；open.ys7.com 仍 200）→ nuclei 后半程 matched=0 **是假阴性**（请求全打在 WAF 上）。**扫描期间必须定期 curl 基线 URL 自检，一变 403 立刻停**。已停全部扫描、关隧道、移除临时公钥。

### 判定纪律新增两条（写进 HANDBOOK）
1. **EdgeOne WAF 拦截页返回 200**：job.ezviz.com 状态码 200 但 body 是「请求已被站点的安全策略拦截…由 Tencent Cloud EdgeOne 提供防护」→ 只看状态码会把 WAF 页当正常页。与「疑似调试页 = WAF 拦截页」同源。
2. **AWS ELB 悬空 CNAME 不可接管**：`ezchat.ezvizlife.com → mars-portal-166682297.eu-central-1.elb.amazonaws.com`（NXDOMAIN，Cloudflare+Google DoH 双证）看似经典接管，但 AWS 给 ELB DNS 加了**熵后缀**（用户只能控 `-` 前的名字，hash 不可预测也不可创建）→ can-i-take-over-xyz 明确 AWS ELB = not possible。**只能报「DNS 残留/悬空 CNAME（信息类）」，不得写成子域接管**。同理 `job.ezvizlife.com → *.wswebcdn.com`（网宿 CDN）NXDOMAIN，可接管性未验证。
3. **验证「未命中」是否可信**：先确认请求真的打到了源站（基线 200），否则 matched=0 毫无意义。
